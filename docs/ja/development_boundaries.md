# 開発時の責務境界

[简体中文](../zh-CN/development_boundaries.md) | [English](../development_boundaries.md) | [繁體中文](../zh-TW/development_boundaries.md) | **日本語** | [한국어](../ko/development_boundaries.md)

Windows ランタイムは `sunpack/sunpack_runtime` にあります。依存の向きは `runtime → pipeline → core` です。pipeline と core は既存のアーカイブ解析、I/O、ファイルシステムモジュールを利用します。

| レイヤー | 責務 |
| --- | --- |
| `runtime` | CLI と Watch の入口、ランチャーの永続セッション、NTFS/ReFS の準備完了判定、Watch 状態、トレイ、通知 |
| `pipeline` | 検出、展開の受付、worker への依頼、再帰処理、チェックポイント、整理 |
| `core` | 型付き設定、パスワードのスナップショット、ローカライズ、リソースパス、共通 Windows プロセス機能 |
| ネイティブ計算 | 形式解析、論理リーダー、分割巻の関連付け、パスワード確認、ディレクトリ走査、出力一覧 |

CLI と Watch は同じ型付きリクエストを `pipeline::Engine` に送ります。探索時の構造解析で論理入力のレイアウトと構造情報を確定し、パスワード確認、worker の計画、復旧、レポートがその状態を再利用します。JSON へのシリアル化は CLI・診断・永続化の境界で行います。既存の SPBF プロトコルで C++ worker に実行用データを渡します。

## アーカイブの識別と復旧

一つの物理入力に複数の独立した論理アーカイブが入ることがあります。それぞれに元データの範囲、結果、復旧チェックポイントがあります。物理入力の整理は、そのグループに含まれる論理タスクの結果がすべて確定してから行います。チェックポイントには元ファイルの世代と出力の識別子を記録し、現在の検出結果に照合できる場合は選択済みの分割巻の組み合わせを保持します。パスワードと動作中のリーダーは保存しません。

未確定の分割計画は元データの範囲と順序付きの巻候補を共有します。worker は実行可能な組み合わせを必要時に列挙し、選んだ元ファイルのインデックスを返します。メモリ回収後は現在の組み合わせを再実行します。未確定の組み合わせに依存するパスワード結果は、入力が確定した場合の失敗キャッシュに入れません。

Watch は準備完了判定、再起動時の復旧、永続化を担当します。pipeline は出力の予約、入力の完了、入れ子のアーカイブの昇格を、永続化が必要なファイルシステム遷移の時点で通知します。復旧時には元ファイルと出力の識別情報を照合してからチェックポイントを再利用します。

## ライフサイクルとテスト

ディレクトリとパスワードのスナップショット、およびコンパイル済みフィルターは実行中の作業に貸し出すか共有します。入力と出力の確保はリクエストの終了時に解放します。計算コアの正しさはネイティブテストが検証し、Python のブラックボックステストはネイティブ実行ファイルやスクリプトを起動してユーザーに見える結果を検証します。
