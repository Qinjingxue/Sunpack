# 開發邊界

[简体中文](../zh-CN/development_boundaries.md) | [English](../development_boundaries.md) | **繁體中文** | [日本語](../ja/development_boundaries.md) | [한국어](../ko/development_boundaries.md)

Windows 執行階段位於 `sunpack/sunpack_runtime`。模組依賴方向為 `runtime → pipeline → core`。排程層和共用基礎層使用現有封存檔分析、I/O 和檔案系統模組。

| 層 | 職責 |
| --- | --- |
| `runtime` | CLI 與 Watch 入口、啟動器工作階段、NTFS/ReFS 就緒判斷、Watch 狀態、系統匣和通知 |
| `pipeline` | 發現、解壓縮準入、worker 請求、遞迴處理、檢查點和清理 |
| `core` | 類型化設定、密碼快照、本地化、資源路徑和共用 Windows 程序設施 |
| 原生計算模組 | 格式分析、邏輯讀取、分卷關系、密碼探測、目錄掃描和輸出清單 |

CLI 和 Watch 都向 `pipeline::Engine` 提交類型化請求。發現階段完成封存檔結構分析並確定邏輯輸入配置，密碼探測、worker 規劃、復原和報告重用該狀態。JSON 序列化位於 CLI、診斷及持久化邊界。C++ worker 透過現有 SPBF 協議接收執行所需資料。

## 封存檔識別資訊與復原

一個物理檔案可包含多個獨立邏輯封存檔。每個邏輯輸入有獨立的源範圍、結果和復原檢查點。物理組的邏輯任務處理完畢後統一清理來源檔案。檢查點記錄來源檔案代次及輸出識別資訊，並在與目前發現結果匹配時重用已選中的分卷組合。檢查點不持有密碼或活動 reader。

不確定的分卷計劃共用源範圍和有序槽位候選域。worker 惰性枚舉可行組合並傳回選中的源索引。記憶體撤回後重放目前組合。依賴未確定分卷配置的密碼結果不能進入針對確定輸入的失敗快取。

Watch 負責就緒判斷、重新啟動復原和持久化。排程層在相應檔案系統操作的邊界發行輸出占用、邏輯輸入完成及巢狀封存檔提升等狀態。復原時核對來源檔案和輸出識別資訊，再重用檢查點。

## 生命週期與測試

目錄快照、密碼快照和編譯後的過濾器在活動任務期間借用或共用。請求結束時釋放輸入與輸出占用。原生正確性測試涵蓋計算核心。Python 黑箱測試執行原生程式或腳本，檢查使用者可見結果。
