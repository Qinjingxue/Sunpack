# 开发边界

[English](../development_boundaries.md) | **简体中文**

Windows 运行时位于 `native/sunpack_native`。模块依赖方向为 `runtime → pipeline → core`。调度层和共享基础层使用现有归档分析、I/O 和文件系统模块。

| 层 | 职责 |
| --- | --- |
| `runtime` | CLI 与 Watch 入口、启动器会话、NTFS 就绪判断、Watch 状态、托盘和通知 |
| `pipeline` | 发现、解压准入、worker 请求、递归处理、检查点和清理 |
| `core` | 类型化配置、密码快照、本地化、资源路径和共享 Windows 进程设施 |
| 原生计算模块 | 格式分析、逻辑读取、分卷关系、密码探测、目录扫描和输出清单 |

CLI 和 Watch 都向 `pipeline::Engine` 提交类型化请求。发现阶段完成归档结构分析并确定逻辑输入布局，密码探测、worker 规划、恢复和报告复用该状态。JSON 序列化位于 CLI、诊断及持久化边界。C++ worker 通过现有 SPBF 协议接收执行所需数据。

## 归档身份与恢复

一个物理文件可包含多个独立逻辑归档。每个逻辑输入有独立的源范围、结果和恢复检查点。物理组的逻辑任务处理完毕后统一清理源文件。检查点记录源文件代次及输出身份，并在与当前发现结果匹配时复用已选中的分卷组合。检查点不持有密码或活动 reader。

不确定的分卷计划共享源范围和有序槽位候选域。worker 惰性枚举可行组合并返回选中的源索引。内存撤回后重放当前组合。依赖未确定分卷布局的密码结果不能进入针对确定输入的失败缓存。

Watch 负责就绪判断、重启恢复和持久化。调度层在相应文件系统操作的边界发布输出占用、逻辑输入完成及嵌套归档提升等状态。恢复时核对源文件和输出身份，再复用检查点。

## 生命周期与测试

目录快照、密码快照和编译后的过滤器在活动任务期间借用或共享。请求结束时释放输入与输出占用。原生正确性测试覆盖计算核心。Python 黑盒测试运行原生程序或脚本，检查用户可见结果。
