# IOCP 全格式 300 MiB 回归短测

2026-10-02，i9-13980HX / Samsung NVMe，基于 HEAD `e181826b` 的工作区。

全格式没有全面退化，但不能说全部无退化：`.zst` 8 并发的三轮配对中，返回时间均较慢，中位数约慢 9.6%；含刷新中位数只慢 1.4%。Gzip、TGZ、TXZ 并发有收益，混合任务接近持平。没有显著增加 RSS。

## 口径

18 个格式/变体，每任务 300 MiB（150 MiB 重复文本 + 150 MiB 确定性随机），单任务和 8 并发各两轮配对；另外 18 个异构任务、最大 8 并发两轮。第二轮反转旧 writer / IOCP 顺序。疑似退化的 Gzip 单任务、RAR5 非 solid 8 并发、Zstd 单任务与 8 并发各补一轮。共 756 个解压任务输出通过 Rust 逐字节校验。

默认预取、4 个 writer 消费线程、原有 1 MiB / 64 缓冲 / 每文件 8 MiB / 每任务 32 MiB 额度；不修改格式线程配额。Release、诊断 probe 关闭。同机交替测量，不清空输入缓存。

返回后立即通过 Rust `sync_all()` 刷新全部输出，随后才校验和清理。含刷新总时间包括驱动采样/收尾及辅助进程启动开销；不能视为纯磁盘时延。此次回归比较旧 writer 与 IOCP，没有重测 CLI。短测的数毫秒或几个百分点波动不适合作稳定归因。

该全矩阵的 IOCP 构建 SHA256 是 `05FBBB30557D23A7276D957E25867D4A35B24989DEA3CFE9E3721B64F3579AF2`；旧 writer 是 `AA24CC1DE06B6C1E42500D988846A2440811978CB39EF9CE72B82D6973B3EA92`。之后进行了满盘/取消/磁盘策略适配；其线程数测量使用另一份当前构建，指纹记录在各 JSON 内，不混为同一次实验。

## 疑似项补测

- `.zst` / 8：三轮返回分别为 451.6→459.4、447.2→497.0、423.5→490.2 ms，都变慢。三轮中位数 447.2→490.2 ms（+9.6%）；含刷新 806.8→818.3 ms（+1.4%）。返回边界有退化，但未发现稳定的落盘总耗时明显退化；尚不能据此确定原因。
- Gzip / 1：初测两轮返回都变慢，补测 88.9→73.1 ms，反向变快。不能认定稳定退化，也不能把补测当作全部无退化的证明。
- RAR5 non-solid / 8：初测 +10.7%，补测 514.9→451.8 ms，反向变快；三轮含刷新中位数接近持平。
- `.zst` / 1：补测 92.0→87.2 ms，初测轻微退化未稳定重现。
- ZIP 单任务、BZip2 并发等小幅变化只有两轮，保留原始结果，不作确定退化归因。

混合 18 任务、最大 8 并发：返回 2637.2→2553.8 ms（-3.2%），含刷新 2828.5→2759.4 ms（-2.4%）。RSS 变化最大约 +5.4 MiB，没有扩大输出缓冲预算。

## 正确性与后续适配

后续将满盘恢复改为事件驱动的 IOCP 队列：不再创建恢复协调线程；保留 ProbeLease 到真实完成后结算。open/close/flush 每次只尝试一次，空间失败保留原缓冲和句柄等待事件；取消、关闭及关停走同一套结算。最终策略统一为每卷默认 8 个 IOCP 消费线程，不区分磁盘类型、不额外限制在途 I/O 请求数；原有缓冲内存预算保留。

最终 6 个 native CTest 通过，包括新增非阻塞 gate 裁决/弱订阅寿命、同卷排队取消及生产者取消/关停。请求数配额和对应测试已随策略删除。99 项 Python 测试通过；8 项真实 VHD 满盘测试因无管理员权限跳过，真实物理满盘未在本机重测。
