# 개발 계층의 책임 범위

[简体中文](../zh-CN/development_boundaries.md) | [English](../development_boundaries.md) | [繁體中文](../zh-TW/development_boundaries.md) | [日本語](../ja/development_boundaries.md) | **한국어**

Windows 런타임은 `sunpack/sunpack_runtime`에 있습니다. 의존 방향은 `runtime → pipeline → core`입니다. pipeline과 core는 기존 압축 파일 분석, I/O 및 파일 시스템 모듈을 사용합니다.

| 계층 | 책임 |
| --- | --- |
| `runtime` | CLI와 Watch 진입점, 실행기 세션 유지, NTFS/ReFS 준비 확인, Watch 상태, 알림 영역 아이콘과 알림 |
| `pipeline` | 검색, 압축 해제 접수, worker 요청, 재귀 처리, 체크포인트 및 정리 |
| `core` | 타입이 지정된 설정, 암호 스냅샷, 현지화, 리소스 경로 및 공용 Windows 프로세스 기능 |
| 네이티브 연산 | 형식 분석, 논리 리더, 분할 볼륨 관계, 암호 확인, 디렉터리 검색 및 출력 목록 |

CLI와 Watch는 동일한 타입의 요청을 `pipeline::Engine`에 보냅니다. 검색 단계에서 구조를 분석하여 논리 입력의 배치와 구조 정보를 얻습니다. 암호 확인, worker 계획, 복구 및 보고는 이 상태를 재사용합니다. JSON 직렬화는 CLI, 진단, 영속화 경계에서 수행합니다. C++ worker에는 기존 SPBF 프로토콜로 실행에 필요한 데이터를 넘깁니다.

## 압축 파일 식별과 복구

물리 입력 하나에 여러 개의 독립적인 논리 압축 파일이 들어갈 수 있습니다. 각 논리 입력은 자체 소스 범위, 결과 및 복구 체크포인트를 가집니다. 한 물리 그룹의 논리 작업을 모두 확정한 뒤 원본을 정리합니다. 체크포인트에는 원본의 세대와 출력 식별자를 기록합니다. 현재 검색 결과와 대응시킬 수 있을 때는 선택된 분할 볼륨 조합도 유지합니다. 암호와 현재 열린 리더는 저장하지 않습니다.

미확정 분할 계획은 원본 범위와 순서가 지정된 슬롯 후보를 공유합니다. worker는 가능한 조합을 필요할 때 열거하고 선택한 입력 인덱스를 돌려줍니다. 메모리 회수 후에는 현재 조합을 재실행합니다. 미확정 분할 조합에 의존하는 암호 결과는 입력이 확정된 경우의 실패 캐시에 넣지 않습니다.

Watch는 준비 판단, 재시작 복구 및 영속화를 담당합니다. pipeline은 출력 예약, 입력 완료 및 중첩 압축 파일 승격을 기록해야 하는 파일 시스템 전환 시점에 보고합니다. 복구 시 원본과 출력 식별자를 검사한 뒤 체크포인트를 재사용합니다.

## 수명과 테스트

폴더·암호 스냅샷과 컴파일한 필터는 활성 작업 동안 빌리거나 공유합니다. 요청이 끝나면 입력과 출력에 대한 점유를 해제합니다. 네이티브 테스트는 연산 코어의 정확성을 검증합니다. Python 블랙박스 테스트는 네이티브 실행 파일이나 스크립트를 실행하여 사용자에게 보이는 결과를 확인합니다.
