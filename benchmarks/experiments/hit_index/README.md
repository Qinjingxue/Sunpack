# 命中索引 benchmark：协议和基线

本轮只完善评估工具和数据，不修改生产索引，也不将已有编码技术称为新增论文贡献。
正式协议见 [PROTOCOL.md](../../hit_index/PROTOCOL.md)，运行入口为 `python -m benchmarks scan hit-index`。

## 固定的比较范围

17 个基线、21 个块长配置：原生产 SunPack、两种原始数组、StreamVByte/0124、SIMD-BP128、FastPFOR、OPTPFor、Simple8b、VSE、EF、均匀/优化分区 PEF、两种 CRoaring 组织及原版/修复 FAW。
实际调用固定 commit 的成熟库和作者源码。保留类型、重复偏移、重复元组、绝对 u64 地址；目录、padding 和类型表示均计费。
完整元组及查询序列的校验与计时分开；失败和 unsupported 不删除，也不作为有效性能结果。

公共类型列为全局单类型保留直接表示，其他情况采用局部 palette。不能用低效适配器或逐项 FFI 制造成熟算法劣势。
FastPFOR 使用原库 SIMD 前缀和，SVB 使用融合差分；FAW 的两个局部修复有独立标签和原始失败记录。

## 数据与结论边界

- 178 个边界/语义输入构成完整 conformance。
- quick 包括 14 个合成输入、按基数分桶选择的 34 个公共集合、13 个真实扫描轨迹，共 61 个输入；三轮进程对比共 3843 个单元。
- 两个公共数据集各有 200 个集合；按固定种子选择，不按 SunPack 的表现选择。
- 真实轨迹来自实际 Rust 后过滤匹配事实。输入覆盖加密、伪装分卷、非首卷、嵌套、载体、空文件和多条目 ZIP。
- 多条目 ZIP 分固定长度和变长混合大小两类。固定长度产生近等差偏移，不能独自代表真实 ZIP，也不能据此宣称新算法原创。
- 正式合成矩阵有 1620 个输入、5 个评估种子；按 7 个进程 block 执行，支持顺序分片和严格合并。

真实格式 fixture 是可控系统输入，不是用户档案的随机样本。Gov2/ClueWeb、更多成熟压缩库、真实用户目录和跨 CPU 推广未由默认 quick 证明。
当前比较也不是纯整数 kernel 测速，不能从完整类型索引的时间反推原库 unpack 指令的速度。

## 已完成的开发基线

2026-11-03，i9-13980HX、Windows x64、Clang 19.1.5、Rust 1.94.1。178 个 conformance 输入中 SunPack 无错误。
最终 quick 的 3843 个单元中，3813 个有效、12 个 unsupported、18 个 invalid；后两类分别来自 roaring-packed 的重复元组限制和原版 FAW 的已记录缺陷，没有 SunPack 错误。
144 次 Builder 重放、36 轮同进程构建释放、39 次完整扫描全部通过；有限 12 轮观察中的释放后句柄均保持 50。

这些数据支持三个后续方向：补强顺序消费；处理异常间隔对压缩率的影响；在分区/检查点设计中同时计入定位成本。
它们也解释为什么不能预设全面领先：PEF 的更小空间可能伴随明显更慢的构建，大块 FastPFOR 的空间收益会损害随机定位，固定长度 ZIP 上的优势在变量长度 ZIP 上大幅缩小。
这些是开发证据；完整 1620 输入确认矩阵和外部真实 workload 尚未运行，不能写成最终论文结论。

## 后续优化应如何使用它

先登记目标分布、主指标、预期效应及可接受退化，再用开发种子调参。锁定实现后运行评估种子。
分别观察空间、构建、顺序消费、类型筛选、随机定位、前向跳转、释放与常驻资源；使用配对结果和分层不确定区间，不合成任意加权的“总分”。

规律偏移上的优势需要与成熟的预测、差分和游程表示核对；不能只战胜这里列出的通用 D1 编码就宣布等差表示原创。
异常间隔和密疏转换上的优势必须包含定位辅助信息、分区规划和构建成本；不能把无查询目录的空间和有目录的速度拼在一起。
类型/重数表示的优势必须保持完整 multiset 语义，不能用去重来减小索引。

Builder 评估运行真实 prepare/push/finish，包含稠密百万命中、稀疏槽表、落盘及多种完成次序。
同一进程 12 轮构建释放用于观察句柄、映射和私有内存趋势，不构成无限时长的无泄漏证明。
完整扫描从真实 Session 开始至 close/资源清理；原始捕获的仪器开销不参与性能结果。
生产接入仍需既有 CLI/Watch 并发集成评价；这里的单索引查询没有证明多读者共享同一游标的吞吐。
