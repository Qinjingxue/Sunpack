# 写入阶段识别实验

2026-11-05。论文、成熟实现、信号审计与开发消融见 [RESEARCH.md](RESEARCH.md)。可机器读取的当前结果见 [phase_results.json](phase_results.json)。

## 计时定义

主指标 `mean_ready_to_valid_proposal_seconds` 的起点是内容完整、目标路径可见、分卷齐备且句柄已允许处理的首个时刻 `processing_ready_at`；终点是首次实际有效提案。独占句柄释放前的时间不计入。所有已就绪但未有效提案的输入仍单独计数，绝不记作零延迟。

写入轨迹合同为 `sunpack.writer-behaviour/2`，计分合同为 `sunpack.quiet-window/5`。起点修订后，两策略均从原始完整提案时间线统一重新评分；14,592 条 outcome 记录逐项确认提案时间及首个有效提案未改变，没有重新运行调度器，也没有增加历史兼容入口。原始回放资源数保留为原始测量，不能当成此次评分的资源消耗。

## 实验设计

28 个复杂写入者、四个观察通道、普通/分卷宽度及代表性的 8/64 文件并发、两种同刻顺序。development、validation、heldout 各 8 个 seed；总计 3,648 条轨迹、38,112 个物理文件、4,264,624 条交付观察。每个划分有 10,624 个完整且可处理的逻辑输入，以下绝对数量已去掉同刻顺序的重复计数。

先在 development 选择模型及无量纲比率，再冻结并运行另外两个划分。未完成默认 16 seeds 的全部设计。对照是原有无阶段过滤的估计器，在同一当前调度/元数据链路中执行；冻结控制源码只补齐新增接口字段和忽略的参数，不增加新模型的训练逻辑。它不是旧版完整二进制的性能对照。

## 实现

- 正常阶段保留最近 12 个时间戳样本、真实时间衰减加权 P90，以及原线性 + 对数等待映射。
- 未知频率或超过当前有效间隔 8 倍的间隔先隔离，不拉长等待；下一条有效间隔若与其相差不超过 2 倍，才建立新的慢速阶段。正常写入恢复时丢弃隔离间隔。确认不阻止现有提案，不是最小等待或最小收缩样本数。
- 既有 USN CLOSE 原因提供独立的句柄阶段边界，断开间隔链；它既不直接触发有效提案，也不证明内容完整。元数据关闭记录即使在 tracker 退休后到达，也会更新同一 Rust catalog 行的阶段摘要。
- 截断及文件身份替换重置旧阶段；元数据恢复、重复通知和边界探测不会训练虚假的写入间隔。
- 常驻状态仅增加两个 f64；十二个样本仍在 tracker 退休时释放。没有新增轮询、文件内容读取、档案分析链路、依赖、固定等待上下限或半衰期秒数。

## 性能与正确性

7 个新进程交替执行原估计器与当前估计器，每次至少 500,000 条观察、4,096 个 tracker。CPU 配对比值中位数 1.008；两个独立中位数为 3.903μs 与 3.966μs/观察。进程间波动较大，配对比值范围 0.702–1.445，不能据此声称精确的 0.8% 成本变化。

活跃 Python tracker 测得约 1,991 → 2,006 字节，约增加 16 字节；常驻 Rust observation 另增加 16 字节。释放 tracker 后未看到随 tracker 数保留的采样历史。

原始虚拟回放的元数据 probe 增加约 13.8%，readiness probe 增加约 3.06 倍，回放 CPU 增加约 23%。这些回放使用相同 dev-profile 原生模块，并将不变的 busy 重试解析合并，不能解释为生产 CPU 或实际 IO 次数。增加的尝试确实可能增加下游工作；这里保留资源数据而不以 tracker CPU 持平掩盖它。开发环境最终已安装优化的 release 原生扩展。

相关 Watch/CLI 正确性检查 405 项通过；临时隔离 Broker 下 45 项真实链路检查通过，包含同大小覆盖、恢复 mtime、NTFS CLOSE、密码及分卷路径。release 构建后又完成 51 项相关检查和 6 项真实 NTFS 检查；临时服务均已卸载。本次没有新增仅用于证明 benchmark 自身可运行的测试。
