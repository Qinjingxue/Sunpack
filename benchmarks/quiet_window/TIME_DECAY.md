# 自适应时间衰减 P90 实验

日期：2026-11-05。初始对照见 [BASELINE.md](BASELINE.md)，评估规则见 [PROTOCOL.md](PROTOCOL.md)。候选由用户预先指定；本轮不按 heldout 结果调参。基线的 heldout 已公开，因此这是固定语料配对比较，不宣称全新盲测。

## 最终算法

每文件保留最近 12 个 `(写入间隔 Δ_i, monotonic 观察时间 t_i)`，仅在有效的真实内容间隔到来时更新。元数据、重复观察和 `learn_interval=False` 的边界探测不学习等待时间，也不单独缩短窗口。

1. `H = 2 × median(最近三个 Δ)`；不足三个时使用已有样本的中位数，两样本取中点。
2. `w_i = 2 ** (-(t_n - t_i) / H)`，相对于最新有效样本计算。每次按当前 H 重算有限历史的权重，数值下溢为零的旧样本不参与分位数。
3. `Q = inf{x: Σ(w_i × 1[Δ_i <= x]) >= 0.9 × Σw_i}`。使用加权经验分位数，不做旧版等权线性插值。
4. 按用户后续要求保留原有等待映射：`quiet = Q + 0.75 × log1p(Q / 2)`。

没有观测间隔时仍为零等待。删除 `minimum_shrink_samples`、`shrink_time_constant_seconds` 及整个 `adjusted_seconds` 旧路径；新分布直接决定增长和下降。半衰期不采用固定秒数，不设静默最小/最大时间。保留映射中的 2 秒仍是原有对数曲线的尺度，因此最终等待映射不具有严格的时间单位缩放不变性；区间估计本身具有该性质。

例：先观测到 20 秒间隔，随后每 0.1 秒写入，前 3 次仍保留长间隔影响，第 4 次（0.4 秒后）Q 降到约 0.1 秒，最终 quiet 由约 21.798 秒降至约 0.1366 秒。没有额外的快速模式或收缩平滑。后续再次出现长间隔时立即重新学习。

时间戳随有限历史一同退休，不创建后台计时器、空闲轮询或跨文件缓存。沿用生产 tracker 的创建、恢复和释放路径；恢复的 quiet 标量在下一次有效间隔到来后由新估计替代。CLI 和 Rust 归档分析/密码/分卷链路没有新增实现。

参考模型边界：[Pandas `ewm(times=...)`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.ewm.html)提供真实时间半衰期模型，但该接口的时间权重只用于均值；[Dropwizard reservoir](https://github.com/dropwizard/metrics/blob/release/4.2.x/metrics-core/src/main/java/com/codahale/metrics/ExponentiallyDecayingReservoir.java)和 [WeightedSnapshot](https://github.com/dropwizard/metrics/blob/release/4.2.x/metrics-core/src/main/java/com/codahale/metrics/WeightedSnapshot.java)体现近期加权分布，但使用采样及自身分位数定义；这里没有照搬它们的实现或引入依赖。自适应 H 和经验 P90 是本次明确指定的组合，不是这些项目已验证的文件完成判定器。

## 完整配对结果

[本轮报告](time_decay.json)与初始 `baseline.json` 使用字节相同的语料、相同评估器源码身份和评分设置。完整执行 9600 条轨迹、76800 个文件、13861720 次送达观察，8 个算法 × 2 种同刻次序，共 153600 条算法/轨迹/次序结果；每个划分 16 个独立 seed block。候选回放约 602.9 秒（包括语料读写和结果汇总）。七个对照算法的全部 seed-level 评分均与初始报告一致，变化仅来自生产 adaptive。

下表为 heldout、等权 family 的 macro mean；差值是新减旧，区间为 2000 次 seed-block 配对 bootstrap 的 95% 区间。比例差值用百分点（pp），不是相对百分比。过早提案是估计器输出，不代表 Watch 原生就绪检查放行或实际解压损坏。

| 指标 | 原始算法 | 时间衰减 P90 + 原等待映射 | 配对差值 [95% 区间] |
|---|---:|---:|---:|
| 过早提案 / 文件 | 2.357 | 2.924 | +0.567 [0.518, 0.618] |
| 至少一次过早提案的文件比例 | 89.62% | 89.62% | 0 pp [0, 0] |
| 完成后未检出 | 3.58% | 3.41% | -0.18 pp [-0.76, 0.47] |
| 500ms 内检出 | 45.02% | 55.40% | +10.38 pp [9.56, 11.13] |
| 2s 内检出 | 63.37% | 75.07% | +11.70 pp [10.89, 12.54] |
| 10s 内检出 | 78.62% | 86.55% | +7.93 pp [7.19, 8.70] |
| 条件平均检出延迟（秒） | 29.550 | 12.576 | -16.974 [-29.223, -5.508] |
| 仍占用时的提案 / 文件 | 0.0758 | 0.0945 | +0.0188 [0.0121, 0.0254] |

development / validation / heldout 的过早提案分别为 2.957 / 2.986 / 2.924 次每文件，500ms 内检出分别为 54.70% / 55.19% / 55.40%，方向一致。heldout 的过早提案相对增加约 24.1%；完成后未检出的差值区间包含零，不能据点估计宣称该风险明显改善。首次等待同为零，二值“至少一次过早提案”也不能表示学习质量。条件延迟的检出集合可能变化，应与包含全部完成文件的预算指标一起看。

分层显示的取舍也不应省略：heldout 的 bursty family 过早提案从 1.705 增至 4.705 次每文件，条件平均延迟从 3.074 增至 3.953 秒；periodic_flush 的 500ms 内检出从 22.5% 降至 2.5%。另一方面，decelerating 的过早提案从 19.275 降至 9.813，长暂停后恢复、加速和空文件后写入的预算指标明显变好。这些 family 行是描述性诊断，不能当作逐 family 显著性检验；完整分层保存在 JSON。

结论是更快适应新节奏、整体预算内检出提升，同时增加过早提案和 CPU/内存成本，**不是全面优于原始算法**。本轮保留指定候选，不根据这些结果改参数或改变计分。合成估计器结果不外推为真实用户失败率，也不替代长期应用轨迹和完整 Watch/CLI 测量。

## 资源成本

[原始 CPU/分配报告](time_decay_cost.json)使用 7 个新进程、每进程每算法 500,400 次观察（其中 380,700 次内容观察），基线与候选在同一进程内交替先后顺序，分别预热。准备、JSON、磁盘和 tracemalloc 不进入 CPU 计时；构造 tracker 包含在计时内。内存另测共享 policy 的 4096 个满历史 tracker。方法不是机器峰值吞吐或端到端 Watch 性能。

| 指标（进程中位数） | 原始算法 | 时间衰减 P90 + 原等待映射 |
|---|---:|---:|
| CPU / 送达观察 | 1.936 μs | 3.091 μs |
| 活跃 tracker 的 traced bytes | 1056.0 | 1990.3 |
| 4096 个 tracker 释放后残留 traced bytes | 8308 | 7860 |

进程内配对 CPU 比值的中位数为 1.623，范围 [1.548, 1.717]；范围不是置信区间。新算法每观察约增加 1.16 μs，每活跃 tracker 约增加 934 字节，主要用于 12 个间隔的时间戳和样本元组。历史数量仍固定，每次最多处理 12 个样本，复杂度 O(12 log 12)，没有随运行时间增长的样本积累；热路径不再先将完整历史转换成 tuple。释放后的数 KB 包括 Python 分配器等残留，单批测量不构成长时间无泄漏证明。

成本实验源码快照、各进程结果与候选源码位于 `benchmarks/results/scheduling.watch-quiet-cost/20261105T031517Z-1338e752/`。CPU 报告的源码指纹使用归一化换行文本，静默回放报告的策略指纹使用文件原始字节；两者不应直接比较摘要值。
